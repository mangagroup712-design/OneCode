# OneCode QRファイル転送

Cloudflare Pagesで配信できる、ブラウザ間QRファイル転送サービスです。送信側の画面にファイルを小さなチャンクへ分割したQRコードを連続表示し、受信側がカメラで読み取ってブラウザ内で復元します。ファイル本体をサーバーへアップロードする仕組みはありません。

## ページ

- `/` - サービス案内
- `/client.html` - 複数ファイル選択、ドラッグ＆ドロップ、名前変更・削除、画像サムネイル、QR表示
- `/read.html` - カメラ読み取り、正確な受信進捗、複数ファイルの画像・動画・音声・PDFプレビュー、名前変更、ZIP一括ダウンロード

## Cloudflare Pagesへのデプロイ

1. GitリポジトリをCloudflare Dashboardの **Workers & Pages → Pages → Create** から接続します。
2. Framework presetは `None`、Build commandは空欄、Output directoryは `/`（リポジトリルート）にします。
3. HTTPSで公開された `/client.html` と `/read.html` を別々の端末で開きます。

ビルド処理やデータベースは不要です。`worker.js` は、WorkersのAssetsとして同じ静的ファイルを配信したい場合の任意のラッパーです。

## 転送の仕組みと速度

現在は1チャンク600バイト、1枚220msでQRを保持し、データQRは同じ内容を2回、メタ情報QRは4回表示します。タイマーで先に次のQRへ進むのではなく、1枚の描画と保持を完了してから次へ進む直列方式です。複数ファイルは選択順に1ファイルずつ連続転送します。受信側は同じチャンクを重複排除し、`受信済みチャンク数 / 全チャンク数` から進捗を計算するため、表示されるパーセントは推測値ではありません。受信速度は実際に受信したバイト数と経過時間からKB/sで表示します。受信した各ファイルは一覧へ追加され、拡張子を除いた名前を編集してから個別またはZIPでダウンロードできます。初期ファイル容量上限は1ファイル50MBです（メモリ使用量とQR転送時間のバランスによる値）。

### PWAとオフライン動作

HTTPSまたはlocalhostで一度ページを開くと、Service Workerがページ本体・スタイル・アプリスクリプト・QRライブラリ・ZIPライブラリをキャッシュします。以降はインターネット接続なしでもアプリを起動し、ZIP作成まで行えます。ファイル転送そのものは従来どおり、送信画面と受信画面の間でQRを直接読み取るだけです。

速度や安定性を上げる候補:

- 画面の明るさを上げ、送受信端末を近づけ、QRを枠内に固定する（すぐ使える改善）
- チャンクサイズ・QR誤り訂正レベル・表示間隔を端末性能に合わせて調整する（容量と読み取り安定性のトレードオフ）
- 受信確認用の戻り通信を追加して、読み取れたチャンクだけ再送する
- WebRTC DataChannelを併用し、QRは接続情報の交換だけにする（高速だが、同一ネットワークや接続許可が必要）

## セキュリティと制限

- QRにファイル内容が載るため、周囲のカメラや画面録画から内容を見られる可能性があります。機密ファイルは人目のない場所で送ってください。
- 送信側は50MBまでに制限し、受信側は宣言されたサイズとチャンク数を検証してブラウザメモリの過剰消費を抑えています。
- カメラはHTTPSまたはlocalhostでしか起動できません。カメラ映像はブラウザ内だけで処理し、サーバーへ送信しません。
- QRライブラリはjsDelivr CDNから読み込んでいます。完全なオフライン運用やサプライチェーン対策が必要な場合は、ライブラリを固定版でローカル配布し、CSPとSubresource Integrityを追加してください。
